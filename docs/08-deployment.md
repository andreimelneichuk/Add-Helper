# Развёртывание и настройка

> **Состояние.** Проверено локально в Docker: `adhelper check`, `make backup restore-check`, веб-сервер Caddy с собранным интерфейсом и `deploy/smoke.sh`. CI собирает образы и прогоняет ту же проверку. На настоящем сервере с доменом установка ещё не проверялась.
>
> **Что пока не работает в продакшене.** Вход через Яндекс отвечает 503, пока не подключён настоящий провайдер (V1/T4). Действия на площадке отвечают 503 до адаптера Директа (T5). `/` с входом открывает интерфейс на данных сервиса, без входа — запуск (`/?start`), шаги 1–4 работают через сервис и без входа. Подставного прототипа в рабочей сборке нет. Пока нет входа (T4) и адаптера Директа (T5), сервис можно ставить для проверки, но не для владельцев.

## 2. Приложение Яндекса

Приложение заказчика настраивается один раз и используется всеми его пользователями.

1. Создать кампанию в [Директ Про](https://direct.yandex.ru/) на аккаунте разработчика: без неё недоступны настройки API.
2. На [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) создать приложение:
   - Платформа: веб-сервисы.
   - Redirect URI: `https://ВАШ_ДОМЕН/api/auth/yandex/callback`, `https://ВАШ_ДОМЕН/api/accounts/yandex/callback`.
   - Права: `login:info`, `login:email`, `direct:api`, `metrika:read`, `metrika:write`, `passport:business`.
3. Сохранить ClientID и Client secret.
4. В Директе на вкладке «Настройки API» → «Мои заявки» подать заявку на **полный доступ**. Подробно описать приложение, указать актуальную почту. Рассмотрение занимает от часа до трёх рабочих дней, в пик до семи.
5. Проверить в настройках API, что доступ именно полный. Ошибка 58 при одобренной заявке обычно означает тестовый доступ.

Готовый текст заявки будет добавлен сюда после одобрения первой заявки.

## 4. Установка

```bash
git clone <адрес репозитория> ad-helper
```

```bash
cd ad-helper
```

```bash
cp .env.example .env
```

Заполните `.env`:

| Переменная | Назначение |
|---|---|
| `POSTGRES_PASSWORD` | Пароль базы. `make setup` подставляет случайный |
| `TOKEN_ENCRYPTION_KEYS` | Ключи шифрования токенов и реквизитов, формат `имя:base64` из 32 байт, через запятую, новый первым. Создать: `echo "k1:$(openssl rand -base64 32)"`. Пусто — вход отключён. **Потеря ключа делает токены нечитаемыми**, храните его отдельно от копий базы |
| `DOMAIN` | Домен для сертификата Caddy |
| `PUBLIC_BASE_URL` | `https://` и тот же домен |
| `DIRECT_ENABLED` | `true` подключает боевой адаптер Директа. По умолчанию `false`: действия с площадкой отвечают 503, страж шлёт тревогу. Включать после согласования запуска с владельцем. Нужны ключи шифрования и приложение Яндекс ID |
| `DIRECT_API_URL`, `DIRECT_LIVE_URL` | Адреса Директ API v5/v501 и Live v4. Для песочницы `https://api-sandbox.direct.yandex.com` и `https://api-sandbox.direct.yandex.ru/live/v4/json/` |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | Приложение в Яндекс ID с адресами возврата `PUBLIC_BASE_URL/api/auth/yandex/callback` и `PUBLIC_BASE_URL/api/accounts/yandex/callback`. Пусто — вход и подключение кабинета отвечают «пока не настроено» |
| `YANDEX_OAUTH_URL`, `YANDEX_LOGIN_URL` | Адреса Яндекс ID, по умолчанию `https://oauth.yandex.ru` и `https://login.yandex.ru`. Менять только для стенда |
| `TEXT_MODEL_BASE_URL`, `TEXT_MODEL_API_KEY`, `TEXT_MODEL_PROJECT`, `TEXT_MODEL_NAME` | Текстовая модель через любой OpenAI-совместимый API. По умолчанию адрес Yandex AI Studio; для него `TEXT_MODEL_PROJECT` — каталог, модель `gpt://<каталог>/yandexgpt/latest`. Без ключа или модели объявления собираются из шаблонов |
| `JUDGE_MODEL_NAME` | Модель судьи смысла объявлений на том же API. Пусто — судья выключен |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_STARTTLS`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` | Письма о тревогах. Порт 465 — сразу TLS, 587 — с `SMTP_STARTTLS=true`. Пусто — письма ждут в очереди |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_NAME` | Бот от @BotFather, имя без `@`. Пусто — Telegram не подключить |
| `POSTGRES_PORT`, `APP_PORT` | Порты базы и приложения на `127.0.0.1` сервера; наружу не публикуются |

VK Реклама, модель изображений и файловое хранилище пока не настраиваются переменными: сервис их не читает. Переменные появятся вместе с адаптерами (T5–T9), и таблица будет дополнена. `COOKIE_SECURE` (по умолчанию `true`) и адреса Яндекс ID нужны только локальному стенду, compose их не передаёт.

Запуск:

```bash
docker compose --profile production up -d --build --wait
```

```bash
docker compose exec app adhelper check
```

Миграции выполняются автоматически при запуске. Команда `check` проверяет базу, версию миграций, очередь задач, ключи шифрования, адрес сервиса, модели, почту, Telegram и файлы правил. Код выхода не 0 означает, что есть ошибка.

Как устроен веб-сервер. Образ `caddy` собирается из `deploy/web.Dockerfile`: Node собирает интерфейс, Caddy отдаёт его и выпускает сертификат для `DOMAIN`. Правила в `deploy/Caddyfile`:
- `/api/*` и `/healthz` идут в приложение, остальное — файлы интерфейса;
- служебные `/docs` и `/openapi.json` наружу не отдаются;
- тело запроса не больше 1 МБ;
- заголовки HSTS, CSP без внешних источников, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, запрет встраивания во фреймы; заголовок `Server` убран;
- `X-Forwarded-For` от клиента Caddy заменяет, поэтому лимиты по адресу не обойти подделкой заголовка.

## 5. Проверка после установки

```bash
deploy/smoke.sh https://ВАШ_ДОМЕН
```

Скрипт проверяет, что интерфейс открывается, `/healthz` отвечает, закрытый API требует входа, большое тело отклоняется, защитные заголовки на месте, а служебные страницы закрыты. Любая строка `FAIL` — повод не открывать сервис людям.

Когда появится вход через Яндекс (V1/T4):

1. Откройте адрес сервиса и войдите через Яндекс.
2. Подключите кабинет с правами.
3. Запустите `docker compose exec app adhelper check`: все проверки зелёные.
4. Пройдите мастер настройки и создайте кампанию с маленьким бюджетом.
5. Сравните созданные объекты с кабинетом.

## 6. Эксплуатация

| Задача | Как |
|---|---|
| Обновление | `git pull`, затем `docker compose up -d --build`; миграции обратно совместимы в пределах версии |
| Резервные копии | `make backup` кладёт копию в `backups/` (или `BACKUP_DIR`) и удаляет копии старше `BACKUP_KEEP_DAYS`, по умолчанию 14 дней. Запускайте ежедневно по cron и уносите копии на внешнее хранилище: сама команда этого не делает. Ключи шифрования в копию не входят, храните их отдельно |
| Проверка копии | `make restore-check` восстанавливает последнюю копию во временную базу и сверяет схему и журнал; рабочую базу не меняет. Запускайте после каждой копии |
| Восстановление | Остановить `app` и `worker`, затем `docker compose exec -T db pg_restore -U adhelper -d adhelper --clean --if-exists --no-owner < файл`, запустить `adhelper check`. Это заменяет данные рабочей базы. После восстановления сверьте состояние с кабинетом: журнал не знает об изменениях, сделанных после копии |
| Логи | `docker compose logs`, токены маскированы |
| Мониторинг | `/healthz` и `adhelper check`. Служебной панели и писем администратору о сбоях пока нет: внешний монитор настраивает оператор |
| Смена ключей шифрования | Новый ключ добавляется в начало `TOKEN_ENCRYPTION_KEYS`: новые записи шифруются им, старые читаются прежним. Команды перешифровки пока нет, поэтому старый ключ из списка не удаляйте |
| Обновление зависимостей | `uv export --no-hashes | uvx pip-audit -r /dev/stdin` и `npm --prefix frontend audit --omit=dev` перед выпуском; итоги последней проверки — в `docs/02-architecture.md` §8 |

**Аварийная остановка рекламы:** `docker compose exec app adhelper emergency-stop --business <id>`. Команда приостанавливает все активные кампании бизнеса через журнал и по чтению площадки сообщает, что остановлено. Код выхода не 0 значит, что остановлено не всё: остановите рекламу вручную в кабинете Директа. Пока адаптера площадки нет, команда честно отвечает `platform_not_connected`. При недоступной базе она не работает, поэтому держите доступ к кабинету. Даже когда сервис остановлен, лимиты на стороне площадки продолжают ограничивать расход.

## 7. Юридический минимум для эксплуатации

Заказчик как оператор данных самостоятельно:
- публикует политику обработки персональных данных и получает согласия;
- уведомляет Роскомнадзор, если это требуется;
- хранит данные на серверах в РФ;
- проверяет условия использования выбранных моделей.

Шаблоны текстов не заменяют консультации юриста.

## 8. Частые проблемы

Раздел будет заполнен по итогам чистой установки: `58`, `redirect_uri mismatch`, нет баллов, код статистики не найден, сертификат не выпускается.
