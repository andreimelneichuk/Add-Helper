# Проверка и приёмка

## 1. Виды тестов

| Уровень | Что проверяет | Как |
|---|---|---|
| Модульные | Правила, вероятности, бюджетные расчёты, тексты | `pytest` + `hypothesis` |
| Свойства бюджета | Ни одна последовательность действий не даёт сумму лимитов выше `H` | Генерация случайных последовательностей |
| Контрактные | Адаптеры и форматы API | Записанные ответы + сверка с документацией |
| Песочница Директа | Вызовы и схемы | Отдельное задание CI, запускается вручную или ночью. Песочница изолирована и деньги не тратит |
| Симулятор автопилота | Решения на сценариях: сбой, нет обращений, всплеск | Поддельная площадка с управляемыми временем и расходом |
| Сбои | Падение между шагами, 429/5xx, нет баллов, истёкший токен, задержка статистики | Внедрение ошибок в поддельную площадку |
| Интеграционные | Модули и база | PostgreSQL в контейнере |
| Сквозные | Мастер, статистика, откат | Playwright |
| Боевые | Реальный кабинет | Чек-лист и малый бюджет |
| Удобство | Понимание без подсказок | Пользователи вне рекламы, запись сессий |

## 2. Обязательные сценарии автопилота

1. Хорошее объявление, плохая неделя у всего рынка: нет необоснованного отключения.
2. Нет обращений из-за удаления кода статистики: тревога, а не отключение рекламы.
3. Сбой, похожий на октябрьский 2026: разрыв конверсий, режим «только защита».
4. Всплеск расхода при устаревшей статистике: остановка до порога.
5. API недоступен при запущенных кампаниях: не превышаем благодаря лимиту площадки.
6. Падение между изменением лимита и записью результата: согласование без двойного применения.
7. Перенос бюджета: при сбое на втором шаге сумма лимитов не выше.
8. Откат после зависимых изменений.
9. Пользователь изменил объект в кабинете во время теста.
10. Отказ модерации варианта A/B: тест отменён, ресурсы освобождены.
11. Смена месяца, часовой пояс Москвы и недели.
12. Нулевой баланс на счёте.
13. Владелец снимает свою паузу, пока часть кампаний остановлена защитой: включаются только его, каждая после проверки худшего случая (`tests/budget/test_owner_actions.py`, `frontend/e2e/control.spec.ts`).
14. Владелец снижает бюджет: сначала лимиты в Яндексе с подтверждением чтением, потом бюджет; ниже потраченного отказ с минимальной суммой; при сбое снижения бюджет прежний (`tests/budget/test_owner_actions.py`).
15. Владелец меняет район и часы показа: запись на каждую кампанию через журнал, отказ до журнала при расписании короче 8 часов в неделю, потерянный ответ доводится чтением без второй записи, отмена возвращает прежнее (`tests/campaigns/`, `tests/api/test_control.py`, `frontend/e2e/control.spec.ts`).
16. Разбор сайта: адрес во внутреннюю сеть отклоняется до очереди и при соединении; факт без цитаты со страницы и цена не из цитаты не попадают в черновик; черновик не меняет профиль, пока владелец не сохранит; лимит разборов в сутки (`tests/business/`, `tests/api/test_site.py`, сквозной сценарий в `make e2e`).
17. Разбор сайта до входа: черновик виден только с ключом из ответа и не виден бизнесу; лимит по сети /24 или /64, соседние адреса IPv6 его не обходят; общий потолок гостей; форма с чужого сайта не принимается; мастер показывает только факты с цитатами, правка факта снимает цитату, сбой ведёт к заполнению вручную (`tests/business/test_guest_site_reads.py`, `tests/api/test_guest_site.py`, `Start.test.tsx`, сквозной сценарий в `make e2e`).
18. Перенос черновика мастера после входа: возврат на `/?new&start` только из списка, чужая цель ведёт на `/`; черновик переживает перезагрузку при входе и переносится один раз даже при повторе; бизнес, который уже есть, не перезаписывается; план бюджета ниже минимума Яндекса или выше потолка отклоняется с объяснением, хранится в микроединицах и виден только своему бизнесу (`tests/budget/test_plan.py`, `tests/api/test_plan.py`, `tests/accounts/test_flow.py`, `draft.test.ts`, `Start.test.tsx`, два сценария в `make e2e`).

## 3. Матрица приёмки

Критерии заказчика взяты из задания дословно по смыслу.

| № | Критерий | Как обеспечиваем | Проверка и доказательство |
|---|---|---|---|
| 1 | Владелец сам подключает кабинет и запускает рекламу без подсказок | Мастер, язык бизнеса | 3 человека вне рекламы, записи, число обращений за помощью = 0 |
| 2 | Кампании создаются и управляются на площадках | Адаптер Директа, согласование | Сравнение в кабинете Директа по чек-листу |
| 3 | Система сама отключила неэффективное и увеличила бюджет эффективного | Автопилот | Реальная запись журнала и её подтверждение в кабинете |
| 4 | A/B-тест пограничной рекламы, вывод и решение | Эксперименты | Карточка теста, данные, состояние на площадке |
| 5 | История, понятные причины, рабочий откат | Журнал | Откат каждого типа на площадке; оценка текстов пользователями |
| 6 | Статистика совпадает с кабинетами | `Reports`, сверка, настройки | Таблица сравнения за 3 и более периодов, для дней старше 3 суток расхождение только из-за округления |
| 7 | Расход не превысил бюджет | Страж бюджета | Отчёт: лимит и суточный расход по всем периодам; журнал замеров |
| 8 | Свои приложения и кабинеты без изменения кода | Конфигурация | Чистая проверка с другими приложениями |
| 9 | Развёртывание по документации без вопросов | Инструкция | Чистая установка другим человеком |

**Дополнительно оцениваются:**

| Требование | Проверка |
|---|---|
| Маркировка | На боевом объявлении: данные рекламодателя заполнены, токен и пометка есть |
| Креативы | Объявления с изображением и видео прошли модерацию и получили показы |
| Другие площадки | Чек-лист этапа 6 |
| Понятные тексты | Участникам показывают экран и просят пересказать смысл |

## 4. Показатели готовности

До сдачи должны выполняться:
- Покрытие тестами модулей `budget`, `autopilot`, `experiments`, `ledger`: выше 90% строк и все сценарии из §2. Для остальных модулей процент не цель.
- Ни одной открытой критичной ошибки.
- Не менее 4 недель работы пилота без превышения бюджета и потери записи журнала.
- Восстановление из резервной копии проверено.
- Мастер настройки проходится за 15 минут или быстрее без учёта установки кода на сайт.

## 5. Пакет для приёмки

1. Ссылка на сервис и доступ для проверки.
2. Отчёт о пилоте: кабинеты, журнал, расход по дням, примеры решений.
3. Таблица сверки статистики.
4. Запись чистой установки.
5. Известные ограничения.
