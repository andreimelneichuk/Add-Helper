# Проверка и приёмка

## 1. Виды тестов

| Уровень | Что проверяет | Как |
|---|---|---|
| Модульные | Правила, вероятности, бюджетные расчёты, тексты | `pytest` + `hypothesis` |
| Свойства бюджета | Ни одна последовательность действий не даёт сумму лимитов выше `H` | Генерация случайных последовательностей |
| Контрактные | Адаптеры и форматы API | Записанные ответы + сверка с документацией |
| Песочница Директа | Вызовы и схемы | Отдельное задание CI, запускается вручную или ночью. Песочница изолирована и деньги не тратит |
| Симулятор автопилота | Решения на сценариях: сбой, нет обращений, всплеск; две версии правил на истории кабинета (`adhelper simulate`) | Поддельная площадка с управляемыми временем и расходом |
| Сбои | Падение между шагами, 429/5xx, нет баллов, истёкший токен, задержка статистики | Внедрение ошибок в поддельную площадку |
| Интеграционные | Модули и база | PostgreSQL в контейнере |
| Сквозные | Мастер, статистика, откат | Playwright |
| Боевые | Реальный кабинет | Чек-лист и малый бюджет |
| Удобство | Понимание без подсказок | Пользователи вне рекламы, запись сессий |

## 2. Обязательные сценарии автопилота

1. Хорошее объявление, плохая неделя у всего рынка: нет необоснованного отключения.
2. Нет обращений из-за удаления кода статистики: тревога, а не отключение рекламы.
3. Сбой, похожий на октябрьский 2026: разрыв конверсий, режим «только защита».
4. Всплеск расхода при устаревшей статистике: остановка до порога.
5. API недоступен при запущенных кампаниях: не превышаем благодаря лимиту площадки.
6. Падение между изменением лимита и записью результата: согласование без двойного применения.
7. Перенос бюджета: при сбое на втором шаге сумма лимитов не выше.
8. Откат после зависимых изменений.
9. Пользователь изменил объект в кабинете во время теста.
10. Отказ модерации варианта A/B: тест отменён, ресурсы освобождены.
11. Смена месяца, часовой пояс Москвы и недели.
12. Нулевой баланс на счёте.
13. Владелец снимает свою паузу, пока часть кампаний остановлена защитой: включаются только его, каждая после проверки худшего случая (`tests/budget/test_owner_actions.py`, `frontend/e2e/control.spec.ts`).
14. Владелец снижает бюджет: сначала лимиты в Яндексе с подтверждением чтением, потом бюджет; ниже потраченного отказ с минимальной суммой; при сбое снижения бюджет прежний (`tests/budget/test_owner_actions.py`).
15. Владелец меняет район и часы показа: запись на каждую кампанию через журнал, отказ до журнала при расписании короче 8 часов в неделю, потерянный ответ доводится чтением без второй записи, отмена возвращает прежнее (`tests/campaigns/`, `tests/api/test_control.py`, `frontend/e2e/control.spec.ts`).
16. Разбор сайта: адрес во внутреннюю сеть отклоняется до очереди и при соединении; факт без цитаты со страницы и цена не из цитаты не попадают в черновик; черновик не меняет профиль, пока владелец не сохранит; лимит разборов в сутки (`tests/business/`, `tests/api/test_site.py`, сквозной сценарий в `make e2e`).
17. Разбор сайта до входа: черновик виден только с ключом из ответа и не виден бизнесу; лимит по сети /24 или /64, соседние адреса IPv6 его не обходят; общий потолок гостей; форма с чужого сайта не принимается; мастер показывает только факты с цитатами, правка факта снимает цитату, сбой ведёт к заполнению вручную (`tests/business/test_guest_site_reads.py`, `tests/api/test_guest_site.py`, `Start.test.tsx`, сквозной сценарий в `make e2e`).
18. Перенос черновика мастера после входа: возврат на `/?new&start` только из списка, чужая цель ведёт на `/`; черновик переживает перезагрузку при входе и переносится один раз даже при повторе; бизнес, который уже есть, не перезаписывается; план бюджета ниже минимума Яндекса или выше потолка отклоняется с объяснением, хранится в микроединицах и виден только своему бизнесу (`tests/budget/test_plan.py`, `tests/api/test_plan.py`, `tests/accounts/test_flow.py`, `draft.test.ts`, `Start.test.tsx`, два сценария в `make e2e`).
19. Шаги мастера после входа: подключение кабинета возвращает в мастер; ИНН с неверной контрольной цифрой, длиной не по типу, без ОКВЭД у организации и ИП или без телефона у физлица отклоняется без эха ИНН в ответе; реквизиты хранятся шифртекстом, чужой шифртекст не расшифровывается; код Метрики ищется в разметке, без сайта не требуется, лимит проверок в сутки; сводка перечисляет, чего не хватает, а без клиента площадки запуск честно недоступен (`tests/accounts/test_marking.py`, `tests/api/test_marking.py`, `tests/api/test_launch.py`, `tests/business/test_tag.py`, `Start.test.tsx`, сценарий в `make e2e`).
20. Объявления мастера до входа: писатель получает только факты черновика, без услуг набор не заказывается; набор видит только ключ, лимит по сети и общий; без модели остаётся шаблон, и это сказано; выбор владельца после входа переходит в бизнес один раз, чужой бизнес его не заберёт; сводка готовности считает выбранные объявления; факты с сайта при переносе попадают в свои поля профиля (`tests/creatives/test_wizard_sets.py`, `tests/api/test_wizard_ads.py`, `draft.test.ts`, `Start.test.tsx`, сценарий в `make e2e`).
21. Запуск из мастера: период и строка запуска пишутся одной транзакцией, кампании создаются только через журнал со снимком «до»; сумма лимитов не выше рабочего бюджета ни в какой момент (свойство через `hypothesis`); кампании, созданные вне сервиса, считаются в бюджет, и запуск отказывает; потерянный ответ площадки доводится чтением по метке без второй кампании; недоступная площадка оставляет запуск «в работе» до повтора; бюджет ниже минимума Яндекса ничего не записывает; действующий период не даёт второго запуска; маркировка уходит на площадку записью журнала до кампаний, реквизиты в журнал не попадают, потерянный ответ доводится чтением, без подтверждённой маркировки кампании не создаются; созданное не откатывается удалением (`tests/campaigns/test_launch_plan.py`, `tests/campaigns/test_launch.py`, `tests/api/test_launch.py`, `Start.test.tsx`; в `make e2e` новый владелец проходит мастер от ссылки до кнопки «Запустить рекламу» на поддельной площадке).
22. Переделка объявления по просьбе: просьба с числом или скидкой не из профиля отклоняется до модели, набор не заказывается; просьба и старый текст уходят писателю строками JSON; почти копия и выдуманная цена сняты кодом; без ответа модели шаблона нет, владелец видит «писатель не ответил»; невыбранные варианты не видны хранителю и списку; выбор второй раз — 409; чужой бизнес — 404; форма не закрывается, когда подробности объявления приходят позже. Сквозной сценарий в `make e2e`.
23. Правка факта: новая цена в профиле сразу даёт замену работающему объявлению со старой ценой, по одной на объявление; повторное сохранение второй замены не заказывает; цена изменилась снова — ждущая замена снимается и заказывается новая; лимит наборов переносит остаток на следующий цикл; без модели замена из шаблона; владелец видит, какие объявления ещё показывают старые цифры. Сквозной сценарий в `make e2e`.
24. Команды чата: частые просьбы разбирает код без модели; модель зовётся, только если правила не узнали, и не больше предела в сутки; её сумма должна быть в сообщении, день назван, объявление и услуга из списков, иначе `unknown`; ничья по словам даёт вопрос, а не догадку; «убери ту, что…» не становится паузой всего; ответ ничего не меняет, выполнение только после «Применить» теми же маршрутами; дни без показа сохраняют часы каждого направления, проверяются все направления до первого изменения, не прочитанные не трогаются; чужой бизнес — 404 (`tests/commands/`, `tests/api/test_chat.py`, `tests/campaigns/test_targeting_changes.py`, `live.test.ts`, сценарий в `make e2e`).
25. Отмена с последствиями: до нажатия владелец видит, что вернётся, и ничего не меняется; если отменить нельзя, видна причина без кнопки; просьба по нескольким направлениям отменяется целиком или по одному; если одно направление изменили в кабинете, не отменяется ни одно; уже отменённые части пропускаются; изменения автопилота не группируются; отменённые записи помечены в истории; чужой бизнес — 404 (`tests/ledger/test_rollback_preview.py`, `tests/api/test_control.py`, `live.test.ts`, сценарий в `make e2e`).
26. Лента «Сегодня»: набор и порядок карточек из правил `today-2`, числа подставляет код; проблема первой, итог недели не говорит «всё в порядке», пока есть проблема; мало данных — так и сказано; лента до 5 карточек, новая тревога без места не теряется; последнее действие сервиса или владельца за неделю с отменой, отменённое и чужое не предлагается; без ленты сервиса экран собирает вывод сам; чужой бизнес — 404 (`tests/stats/test_today.py`, `tests/api/test_control.py`, `Overview.test.tsx`, `live.test.ts`, сценарий в `make e2e`).
27. Тест по итогам анализа: пограничное объявление получает предложение теста только при лимите за срок теста не меньше 4 целевых цен, без идущего теста и не раньше 3 дней после изменения, причём журнал называет причину ожидания; гипотеза только из подтверждённого профилем, проверенные пропускаются; в `confirm` — карточка с цифрами, в `auto` — подготовка сама; ответ — новая запись, повтор и старая карточка — 409; отказ и отмена готовящегося теста держат объявление 14 дней; одобрить тест без варианта нельзя; ни один шаг не меняет площадку; чужой бизнес — 404; данные цикла изолированы по бизнесу (`tests/autopilot/test_decide.py`, `test_test_offer.py`, `test_data.py`, `tests/experiments/test_preparing.py`, `tests/api/test_experiments.py`, `tests/worker/test_autopilot_run.py`, `Overview.test.tsx`; в `make e2e` автопилот на стенде предлагает тест, владелец соглашается и отменяет, журнал изменений тот же).
28. Отправка и проверка Яндексом: объявление уходит в Директ один раз через журнал, потерянный ответ доводится поиском по метке; недоступная площадка ничего не теряет; причина отказа сводится к закрытому набору, и текст площадки не попадает в просьбу писателю; ремонт не больше двух раз, повтор той же причины в направлении, отказ из-за сайта или документов сразу передаются владельцу с тревогой, а отклонённое держит место; одобренная замена отключает старое объявление через журнал, потерянный ответ доводится в следующем цикле; чужой бизнес не затронут (`tests/creatives/test_moderation_plan.py`, `tests/creatives/test_moderation.py`, `tests/notifications/test_messages.py`; в `make e2e` объявления мастера на подставной площадке: отказ из-за сайта ждёт владельца, отказ по тексту переписан, владелец запускает ремонт, Яндекс одобряет, начинаются показы).
29. Снятие объявления сервиса владельцем: «Отключить» идёт через журнал (`pause_ad`, источник `user`), строка объявления становится `stopped` с причиной `owner_stopped`, место в направлении освобождается, тревога об отклонённом закрывается; отмена в истории (`resume_ad`, источник `rollback`) возвращает объявление на чтение проверки Яндекса, и одобренное снова `running`; остановка заменённого автопилотом снятием владельца не считается; повтор цикла ничего не задваивает (`tests/creatives/test_moderation.py`).
30. Тест по итогам анализа до показов: готовящийся тест получает вариант с ценой из профиля через журнал (`create_ad` и `pause_ad`, источник `experiment`), вариант ждёт проверки выключенным; потерянный ответ создания доводится чтением без второго объявления; отклонённый вариант отменяет тест, контроль работает; одобренный чередуется по расписанию Морса, и вариант с заметно большим числом обращений применяется после минимального срока; без подходящего варианта тест отменяется с причиной `no_variant` (`tests/experiments/test_pipeline.py`).

## 3. Матрица приёмки

Критерии заказчика взяты из задания дословно по смыслу.

| № | Критерий | Как обеспечиваем | Проверка и доказательство |
|---|---|---|---|
| 1 | Владелец сам подключает кабинет и запускает рекламу без подсказок | Мастер, язык бизнеса | 3 человека вне рекламы, записи, число обращений за помощью = 0 |
| 2 | Кампании создаются и управляются на площадках | Адаптер Директа, согласование | Сравнение в кабинете Директа по чек-листу |
| 3 | Система сама отключила неэффективное и увеличила бюджет эффективного | Автопилот | Реальная запись журнала и её подтверждение в кабинете |
| 4 | A/B-тест пограничной рекламы, вывод и решение | Эксперименты | Карточка теста, данные, состояние на площадке |
| 5 | История, понятные причины, рабочий откат | Журнал | Откат каждого типа на площадке; оценка текстов пользователями |
| 6 | Статистика совпадает с кабинетами | `Reports`, сверка, настройки | Таблица сравнения за 3 и более периодов, для дней старше 3 суток расхождение только из-за округления |
| 7 | Расход не превысил бюджет | Страж бюджета | Отчёт: лимит и суточный расход по всем периодам; журнал замеров |
| 8 | Свои приложения и кабинеты без изменения кода | Конфигурация | Чистая проверка с другими приложениями |
| 9 | Развёртывание по документации без вопросов | Инструкция | Чистая установка другим человеком |

**Дополнительно оцениваются:**

| Требование | Проверка |
|---|---|
| Маркировка | На боевом объявлении: данные рекламодателя заполнены, токен и пометка есть |
| Креативы | Объявления с изображением и видео прошли модерацию и получили показы |
| Другие площадки | Чек-лист этапа 6 |
| Понятные тексты | Участникам показывают экран и просят пересказать смысл |

## 4. Показатели готовности

До сдачи должны выполняться:
- Покрытие тестами модулей `budget`, `autopilot`, `experiments`, `ledger`: выше 90% строк и все сценарии из §2. Для остальных модулей процент не цель.
- Ни одной открытой критичной ошибки.
- Не менее 4 недель работы пилота без превышения бюджета и потери записи журнала.
- Восстановление из резервной копии проверено.
- Мастер настройки проходится за 15 минут или быстрее без учёта установки кода на сайт.

## 5. Пакет для приёмки

1. Ссылка на сервис и доступ для проверки.
2. Отчёт о пилоте: кабинеты, журнал, расход по дням, примеры решений.
3. Таблица сверки статистики.
4. Запись чистой установки.
5. Известные ограничения.
