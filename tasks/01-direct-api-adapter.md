# Задача 01. Боевой адаптер Яндекс Директ API (`DirectClient`)

- **Приоритет:** P0 (Блокирующий)
- **Сложность:** Высокая (High)
- **Трудозатраты с Claude Code:** 1–1.5 рабочих дня (2–3 сессии вместо 4–6 дней у человека)
- **Зависимости:** Нет (токен логина `andreimelneichuk` уже проверен в боевом API)
- **Блокирует:** Задачи 04, 05, 09, 10

---

## 1. Проблема
В настоящее время все операции управления рекламой (создание кампаний, групп, объявлений, управление лимитами, чтение отчетов) завязаны на абстрактные порты (`BudgetPlatform`, `AdControl`, `AdPublisher`, `TargetingControl`, `CampaignLauncher`), которые реализованы только в тестовом симуляторе (`fake_platform.py`). В кодовой базе нет ни одного реального HTTP-запроса к API Яндекс Директа.

## 2. Что нужно сделать

1. **Создать модуль адаптеров `src/adhelper/platforms/adapters/direct/`:**
   - Реализовать базовый транспорт `DirectHttpClient` с обработкой заголовков `Authorization: Bearer <token>`, `Client-Login`, `Units`, квот (не более 5 параллельных запросов) и повторов с экспоненциальной задержкой при 5xx/429.
2. **Реализовать методы для Единой перфоманс-кампании (Unified Campaign, API v501):**
   - `Campaigns.add` с `CustomPeriodBudget` (лимит на период, дата окончания, микрорубли).
   - `Campaigns.update` для изменения лимитов, расписания показов (`TimeTargeting`) и статуса (`suspend` / `resume`).
3. **Реализовать создание структуры групп и объявлений (API v5):**
   - `AdGroups.add` (таргетинг по регионам `RegionIds`).
   - `Ads.add` (`TextAd` / `UnifiedAd` с заголовками, текстами, ссылками и UTM-метками).
   - `AdControl` (`Ads.suspend`, `Ads.resume`).
4. **Реализовать чтение статистики через сервис отчетов (`Reports`):**
   - Формирование отчета `CUSTOM_REPORT` (поля: `Date`, `CampaignId`, `AdId`, `Cost`, `Clicks`, `Impressions`).
   - Парсинг TSV-ответа отчета в доменные объекты `DailyStat`.
   - Проверка заголовка `Units` (списание баллов).
5. **Интеграция с журналом изменений (`RoutingGateway`):**
   - Подключить реальные адаптеры вместо заглушек в фабрике приложения (`open_runtime`).

## 3. Критерии готовности (Definition of Done)
- [ ] Написан боевой адаптер, покрытый интеграционными тестами на записанных ответах (VCR / `pytest-httpx`).
- [ ] Проведен сквозной тест на реальном кабинете: создание одной тестовой кампании с минимальным недельным лимитом 300 ₽, добавление группы, добавление объявления.
- [ ] Отчет `Reports` успешно прочитан и распарсен, расход совпал с кабинетом.
- [ ] Сервис умеет останавливать кампанию через Direct API при превышении лимита.
