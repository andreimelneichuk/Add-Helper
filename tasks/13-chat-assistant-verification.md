# Задача 13. Гибридный ИИ-ассистент: Read-Only аналитика и безопасные предложения действий (Proposal Pattern)

- **Приоритет:** P1 (Критерий ТЗ «управление простым языком» + безопасность)
- **Сложность:** Средняя (Medium)
- **Трудозатраты с Claude Code:** 2–3 часа
- **Зависимости:** Задача 07 (чистый фронтенд), Задача 01 (Direct API)
- **Блокирует:** Сдача сценария интерактивного управления

---

## 1. Архитектурная концепция: «Мозг отдельно, Руки отдельно»

Решение согласовано 05.11.2026:
* **Агенту категорически запрещено давать Write-инструменты** (прямой доступ к списанию денег, изменению ставок или выполнению произвольного кода). Это исключает уязвимости Prompt Injection со сторонних сайтов и финансовые галлюцинации LLM.
* **Чат работает по гибридной схеме:**
  1. **Read-Only аналитика:** ассистент свободно отвечает на вопросы о рекламе, используя инструменты чтения (`get_summary_stats`, `get_recent_changes`, `explain_metric`).
  2. **Proposal Pattern для изменений:** любые команды на изменение параметров (бюджет, пауза, дни показа) переводятся в визуальную карточку подтверждения: *«Понял так: [Действие]. Применить?»*.
  3. **Исполнение только кодом:** само действие выполняется строго детерминированным ядром сервиса (Политика $\to$ Страж бюджета $\to$ Журнал со снимком $\to$ Директ API) **только после клика пользователя по кнопке «Применить»**.

---

## 2. Что нужно сделать

### А. Бэкенд (`src/adhelper/commands/` и `api/chat.py`)
1. **Инструменты чтения данных (Read-Only Tools для аналитики):**
   - Добавить в контекст ассистента агрегаты статистики: текущий расход за месяц, план, статус кампаний, топ работающих объявлений, последние записи журнала.
   - Поддержать аналитические запросы:
     - *«Как дела с рекламой?»* $\to$ краткая человеческая сводка: сколько потрачено, сколько кликов, все ли в порядке со ставками.
     - *«Что ты делал за последние 3 дня?»* $\to$ выжимка из журнала `changes` простым языком.
     - *«Какое объявление лучше всего работает?»* $\to$ сравнение CTR и лидов.
2. **Распознавание команд управления (Proposal Engine):**
   - Закрытый список интентов:
     - `SET_BUDGET` (смена лимита)
     - `PAUSE_ALL` / `RESUME_ALL` (пауза/старт рекламы)
     - `SKIP_DAYS` (расписание показов)
     - `PAUSE_AD` / `RESUME_AD` (управление конкретным объявлением)
     - `UNDO_LAST` (откат последнего действия)
   - Если пользователь пишет управляющую фразу, бэкенд возвращает JSON предложения:
     ```json
     {
       "type": "proposal",
       "action": "SET_BUDGET",
       "params": {"amount_rubles": 20000},
       "confirmation_text": "Понял так: изменить месячный бюджет на 20 000 ₽. Сначала скорректирую лимиты в Директе, затем сохраню новый план. Применить?"
     }
     ```

### Б. Фронтенд (`frontend/src/app/screens/Chat.tsx` и `live.ts`)
1. **Отображение карточки подтверждения (Proposal Card):**
   - Карточка выводится прямо в ленте чата с кнопками **«Применить»** (зеленая) и **«Не надо»** (нейтральная).
   - Клик по «Применить» вызывает штатный метод `LiveStore.perform(action)` — тот же самый, что вызывают кнопки в настройках.
2. **Стартовые подсказки (Chips):**
   - При открытии чата показывать кликабельные чипсы быстрых действий:
     - `«Как дела с рекламой?»`
     - `«Поставь на паузу»`
     - `«Бюджет 20 000 ₽»`
     - `«Не показывай по выходным»`
     - `«Что ты менял в последнее время?»`
3. **Безопасная обработка неизвестных запросов:**
   - Если запрос не распознан как аналитика или команда, ассистент вежливо сообщает о своих возможностях:
     *«Я умею показывать статистику, менять бюджет, расписание и ставить рекламу на паузу. Напишите, например: "бюджет 15000" или "как дела?"»*.

---

## 3. Критерии готовности (Definition of Done)
- [ ] Ассистент связно отвечает на вопрос «Как дела с рекламой?», используя реальные цифры из витрины статистики.
- [ ] Ассистент отвечает на вопрос «Что ты делал?», транслируя последние записи журнала человеческим языком.
- [ ] Управляющие фразы («пауза», «бюджет 25000», «не показывай по воскресеньям») генерируют карточку подтверждения с кнопкой «Применить».
- [ ] Нажатие «Применить» успешно проводит изменение через `RoutingGateway` и журнал изменений `changes`.
- [ ] Прямой вызов деструктивных действий со стороны LLM невозможен (отсутствуют Write-инструменты в рантайме модели).
