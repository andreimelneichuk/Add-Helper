# Задача 07. Завершение редизайна (R7) и удаление устаревшего UI

- **Приоритет:** P1 (Важный, снижение техдолга)
- **Сложность:** Средняя (Medium)
- **Трудозатраты с Claude Code:** 0.5–1 рабочий день (1–2 сессии вместо 2–3 дней у человека)
- **Зависимости:** Нет
- **Блокирует:** Задача 08

---

## 1. Проблема
Во фронтенде сейчас присутствуют три поколения интерфейса:
1. Старый мастер (`frontend/src/wizard`, `src/screens`).
2. Кабинет в стиле Директа (`frontend/src/cabinet/`).
3. Новый утвержденный дизайн (`frontend/src/app/`, открывающийся по `/?new`).

Параллельное существование трех наборов экранов и зашитых mock-данных (`data.ts`, `live.ts`, `testLive.ts`) создает путаницу при тестировании и мешает связать единый чистый роутинг с бэкенд API.

## 2. Что нужно сделать

1. **Удалить устаревший код:**
   - Полностью удалить директории `frontend/src/cabinet/` и `frontend/src/wizard/`.
   - Удалить устаревшие тесты `Cabinet.test.tsx` и специфичные для них хелперы.
2. **Сделать новый интерфейс основным:**
   - Перенести экраны из `frontend/src/app/` в качестве основного роутинга приложения (`/` вместо `/?new`).
   - Убрать флаги `mock` и временные переключатели в `App.tsx`.
3. **Связать экраны с реальным API:**
   - Заменить заглушки на запросы к бэкенду через единый клиент `frontend/src/api.ts`.
   - Добавить понятные состояния загрузки (Skeleton/Spinner) и обработку ошибок сети.
4. **Обновить спецификацию продукта:**
   - В `docs/01-product-spec.md` и `docs/10-redesign.md` зафиксировать завершение этапа R7.

## 3. Критерии готовности (Definition of Done)
- [ ] Директория `frontend/src/cabinet` удалена.
- [ ] Главная страница по адресу `/` сразу открывает новый утвержденный интерфейс.
- [ ] Команды `make check-web` и `make e2e` проходят успешно.
- [ ] Нет дублирования стилей и неиспользуемых компонентов.
